# HowToEdibles — Static Site

Cannabis edibles recipe site hosted on GitHub Pages at www.howtoedibles.com.

## Architecture

Fully static HTML site — no build framework, no bundler. Almost every page is generated by `scripts/build_site.rb`; only the bodies of English about.html and contact.html are hand-maintained.

- **Hosting:** GitHub Pages (branch: master)
- **Domain:** www.howtoedibles.com (CNAME file)
- **Languages:** en (root), pt, es, de, zh — generated pages live in `/{lang}/`
- **CSS:** one hand-written `/css/site.css` on every page (no Bootstrap, jQuery, Font Awesome or Google Fonts; the redesign #71–#76 finished in Phase 4). The one webfont is the self-hosted `/fonts/unbounded-800.latin1.woff2`
- **JS:** Vanilla JS in `/js/` — no build step, no modules
- **Images:** pages show covers (category colour + dish-form glyph from `data/glyphs.svg`, inlined), no photos. Share/schema images are rendered PNGs in `og/{lang}/{slug}.png` and `schema/{slug}.png`. The old recipe photos in `/images/recipes/` are no longer linked from any page; they're kept for image-search traffic

## Key Commands

```bash
# Rebuild all generated pages (translated homepages, recipes, categories, articles, search indexes, sitemap),
# run the inbound-link gate, render changed og/schema PNGs, then the page-weight budget
# (scripts/check_budget.rb, blocking on every page)
ruby scripts/build_site.rb

# Gates before merging (serve the repo first: python3 -I scripts/qa/serve.py 8781, which gzips text and answers missing paths with /404.html like Pages; lighthouse.sh needs the gzip; another port: BASE=http://127.0.0.1:PORT)
node scripts/qa/devices.mjs   # 36 viewports × 5 langs × recipes, special pages, articles: overflow, first screen, dose readout, rail
node scripts/qa/fit.mjs       # strings: cut-off text and wrapped one-line controls, incl. menu/search dialogs
node scripts/qa/interact.mjs  # calculator, dialogs + Back, theme key
sh scripts/qa/lighthouse.sh   # mobile lab run, ads blocked: LCP ≤ 1.8 s, CLS ≤ 0.02, TBT ≤ 100 ms
ruby scripts/qa/slots.rb      # article ad slots follow the #55 rule in all 5 languages

# Rebuild /fonts/unbounded-800.latin1.woff2 from the pinned upstream font (fontTools + brotli)
python3 scripts/build_font.py

# Rebuild the logo (images/brand/logo*.svg, logo.png, og-image.jpg) and the favicons/apple-touch icon
# from one geometry, text outlined from the pinned Archivo Black (fontTools + rsvg-convert + magick)
python3 scripts/build_logo.py

# Render og/schema PNGs from tmp/rasters/jobs.json (headless Chrome, incremental)
node scripts/render_rasters.mjs

# Generate placeholder images for recipes without photos
python3 scripts/generate_placeholders.py

# Generate real recipe photos via Gemini API (needs GEMINI_API_KEY env var)
python3 scripts/generate_images_gemini.py

# Translate recipe text (ingredients/instructions) via term mapping
ruby scripts/translate_recipes.rb
```

`old_rails/` (legacy Rails 5.2 app) was removed from master on 2026-11-09 because GitHub Pages served it publicly, credentials included. It's gitignored if a local copy exists; it's still in git history.
Everything on master is public on the site — never commit secrets, and keep the Rails-era redirect stubs (`/categories/…`, `/desserts/…`, etc.). The English calculator lives at its Rails-era URL `/edible-dosage-calculator/` (generated); `/calculator.html` is a redirect, and `write_file` rewrites every English link to it. ## Conventions

- **Articles are generated** in all 5 languages from `i18n/articles_{lang}.json` — edit the JSON, never the article HTML (each generated file starts with a "Generated by" comment). `body_html` holds the article body; `<!-- toc -->` marks where the TOC goes. Bodies keep their old Bootstrap markup and are styled by the legacy-compat block in `css/site.css`. The `article-mid`/`article-end` ad slots are inserted by rule at build time (#55; checked by `ruby scripts/qa/slots.rb`), so `body_html` never stores a slot.
- 88 translated article pages (22 articles × pt/es/de/zh) are **frozen**: their `raw_main` is copied verbatim (minus stray `<script>`s) into the new shell, with no ad slots. Some have an English body and 28 have two articles stuck together; their fate belongs to the traffic map. They stay out of the sitemap and the articles indexes.
  **Real translations of all 88 are staged, unpublished,** in `content/translations/{lang}/` (pipeline and rules in that folder; `/content/` is disallowed in robots.txt). To publish, run `python3 -I content/translations/merge.py .`, then `ruby scripts/build_site.rb` and `ruby scripts/check_english_migration.rb`. Publishing day starts their 14-day measurement window (#44).
- Hand-maintained: the **bodies** of English `about.html` and `contact.html`: edit the copy between their `<!-- body -->` markers; the build keeps the title/meta/JSON-LD, rewraps the body in the new shell and refreshes about's facts-row counts. Home, calculator, donate, the articles index and the root 404 are generated in all 5 languages (Phase 2, #74); their English head copy (keywords, schema text) lives in `i18n/en.json` and `i18n/articles_en.json` → `articles_index`.
- Recipe and category pages for ALL languages (including English) are generated by `build_site.rb`, with templates in `scripts/build_redesign.rb`. Everything a crawler needs (the dose sticker, facts, beginner line, the calculator's result panel) is static HTML from the recipe defaults; JS only re-renders on input
- The build fails if any recipe, in any language, has fewer than 2 static inbound links (its category page plus a "More {category}") or is missing from the sitemap
- Cover colours come from `recipes.json` → `categories[].colors` and are emitted inline as `--cat-lt/--deep-lt/--cat-dk/--deep-dk`; CSS picks `--cat` per theme. Never emit `--cat` inline (it defeats dark mode)
- Group recipes by `category_name`: `categories[].recipes` in `recipes.json` is stale
- Ad slots go through `ad_slot` in `build_redesign.rb`; unit ids live in `AD_UNITS`
- After changing article data or the article template, run `ruby scripts/check_english_migration.rb origin/master` (the local `master` ref goes stale). It checks that every English page still matches master on title, meta, canonical, hreflang, JSON-LD and visible text (`--head` skips the text).
- Dosage formula: `dosage_mg = (10 * grams * strength_percent * 0.8) / num_portions` (0.8 = `COOKING_EFFICIENCY` in `build_site.rb` and `js/dose.js`; keep them in sync. The dose ladder, the 5 mg fraction helper and number formatting are mirrored between `build_redesign.rb` and `js/dose.js`; `scripts/qa/devices.mjs` checks they render the same)
- Recipe defaults (`suggested_quantity`) are capped so the default dose is ≤ 15 mg THC per serving
- **Writing or editing a recipe: follow `content/RECIPE_STANDARD.md`** (dose from the site's own base, ≤ 15 mg, split fat; storage only in `storage_unique`; template by cooking method; 5-language parity). Check with `ruby scripts/qa/recipes.rb . --json /tmp/l1.json` (a report for now, not a gate; see `scripts/qa/recipes.rb`)
- Recipe URLs: `/recipes/{slug}/` (directory with index.html)
- The calculator card (recipe pages, homepage, calculator.html) reads `window.DOSE` (injected inline per page); `?quantity=&potency=&portion=` still pre-fill it
- Dark mode uses `[data-theme="dark"]` CSS selectors. The `theme` localStorage key holds `light` or `dark`; Auto removes the key
- Categories: Desserts, Drinks, Snacks, Essentials, Lunch, Keto, Vegan, International

## Data Flow

1. `data/recipes.json` is the single source of truth for recipe metadata
2. `data/recipes_text.json` has full ingredients/instructions
3. `data/recipe_enrichment.json` has tips, variations, pairings, FAQ
4. `i18n/*.json` has all translations
5. `scripts/build_site.rb` combines all of the above → generates HTML
